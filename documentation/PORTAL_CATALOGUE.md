# Portal treatment catalogue and welcome page

After the October 2026 host cutover, this clinic catalogue belongs to `willowwellness.copihue.ca`. The separate `portal.copihue.ca` root is a neutral Copihue landing page, not Willow's catalogue.

The portal root is a public, continuously scrolling catalogue. It uses the already published treatment and practitioner data rather than duplicating descriptions in another CMS. The clinic's welcome title and message are the only new portal-specific editorial copy; a Super Admin edits both languages in Operations → Business settings → Portal welcome message. If not configured, the portal shows translated default copy.

The category navigation follows scrolling and jumps to each category. Category names and descriptions can be edited in Operations → Business settings → Service categories, including French fields. Existing categories have no French translation until an administrator enters one; the English text is the fallback. Treatment names, descriptions, lengths, and prices come from the published service catalogue. Only published practitioner profiles are displayed. A practitioner's image, public title, and public summary are shown in a hover/focus preview, with a separate portal detail page. No private staff profile or appointment data is part of this view.

The portal root is catalogue-only; it does not load the availability form. Each treatment has a public `/services/{slug}/book` URL, and each duration has a distinct `?duration={minutes}` link that preselects its length. These URLs work in a fresh browser without sign-in. The Share action uses the browser's share sheet where available and otherwise copies the link. Practitioner Book actions can preselect the practitioner on a service booking URL or open the public practitioner-first `/availability` page. Older root URLs with booking hints redirect to the appropriate public booking route. Only **Book this time** passes through `/book`, where client authentication, onboarding, approval, and the final availability check remain mandatory. The **Log in** action returns an already linked client to the catalogue after sign-in; clients awaiting onboarding stay in their client workspace.

Published practitioner detail pages at `/practitioners/{slug}` also have a Share/Copy action. The portal deployment rewrites public treatment-booking and practitioner-profile URLs through `share-preview.php`, which inserts a title, description, canonical URL, and Open Graph/Twitter metadata into the existing SPA shell. Metadata comes only from published catalogue/profile fields; unpublished or missing items return HTTP 404. Profile previews use the published image when available, otherwise the clinic logo. The private API's `CLIENT_PORTAL_URL` must identify the HTTPS portal host. The portal ZIP must include its `.htaccess`, `share-preview.php`, and `share-preview-lib.php`; no database migration is required for share previews.

Deploy migration `028_portal_welcome_and_category_translations.sql` after migration 027 and before uploading the updated private API and portal. The public-site archive does not need to change for this feature. This does not implement multi-clinic host resolution: the current API still selects the first active clinic.
